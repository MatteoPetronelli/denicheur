## RiftMind (`C:\Users\era92\Desktop\Matteo\RiftMind`)

Rust workspace + Tauri 2. Git repo.

**Gate** (end of every lot):

```bash
cargo fmt --all -- --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace
```

**Clean-clone proof.** A cold Rust build is slow; point the clone at the existing build cache:

```bash
CARGO_TARGET_DIR="$(pwd)/target" bash ~/.claude/skills/long-run-delivery/scripts/clean_clone_check.sh \
  "cargo test --workspace" "cargo clippy --workspace --all-targets -- -D warnings"
```

What a clone can reveal here: fixtures or recordings that are git-ignored but read by tests, files
generated by a build script, and CRLF in TOML rules or golden files (`core.autocrlf` is on).

**`.claude/run-guard.json`** suggestion:

```json
{ "protected": ["target/", "graphify-out/"], "push": "deny", "forbidTrailers": ["Co-Authored-By: Claude"] }
```

Add the golden fixtures of the diff engine to `protected` during a refactor: a refactor that edits
its own expected output proves nothing.

**Lots.** Dependencies point one way (storage, rofl, mock-server → core; poller → core + storage;
desktop → all), so cut lots in that order and gate with `cargo test -p <crate>` during a lot, the
whole workspace at its end.

**Looking at the UI.** The desktop app needs a desktop session, which an agent does not have. The
front-end in `crates/desktop/ui` can still be driven by `browser-proof` if it is served on its own
with the Tauri IPC mocked; the mock server on :2999 already fakes the game. Port 2999 goes in the
preflight list.

**Tokens.** `python ~/.claude/skills/long-run-delivery/scripts/tokens_by_commit.py` from the repo root.

## dynamic-orchestrator (`C:\Users\era92\.claude\dev-mods\…\dynamic-orchestrator`)

Claude Code plugin, TypeScript, **no git repo, no package.json**.

**Gate** (from the parent directory, as its `CLAUDE.md` says; only the touched test file during a
task, everything at the end):

```bash
claude plugin test ./dynamic-orchestrator && claude plugin validate ./dynamic-orchestrator \
  && npx -y -p typescript@5.6.3 tsc -p ./dynamic-orchestrator
```

**No clean clone** (no Git). The equivalent proof: copy the folder to a temp directory and run
`claude plugin validate` there; it catches a file referenced by `plugin.json` but missing.
Consider `git init`: without history there is no per-lot checkpoint, no revert of a bad lot, and
`tokens_by_commit.py` can only bucket by hour (`--by hour`).

**`.claude/run-guard.json`** suggestion: protect the vendored typings, which must never be edited
or read whole:

```json
{ "protected": [".claude-plugin/types/"] }
```

**What the reference run teaches a router.** The orchestrator picks a model and an effort per
prompt; the measured data in `retrospective-bracket.md` gives it three signals worth a rule each
(ideas, not implemented; check `PROGRESS.md` "Decisioni prese" first):

1. *Context size beats model price.* The same lot cost twice as many tokens per turn at 430 k of
   context as at 215 k. A band warning ("context > 300 k: compact or restart") is worth more than a
   cheaper model.
2. *An expired cache is a cliff.* The first turn after a long pause re-wrote 0.4 to 1.2 M tokens.
   When the last turn is older than the cache lifetime and the context is large, suggest a fresh
   session before sending.
3. *Trial-and-error turns are the waste.* The scaffolding lot took 29 turns, the engine lot 11.
   Tooling and setup prompts deserve *more* effort, not less: a wrong first command costs a full
   context re-read.
